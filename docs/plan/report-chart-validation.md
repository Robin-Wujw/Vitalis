# 验证图表数据与报告接收效果

[改动计划](README.md) · P1 · 状态：本地候选验证通过，待 App 对照与候选发布

## 现在是什么情况

来源隔离的图表 API、独立 SVG/HTML 详情、午睡、厂商七日负荷、readiness 修订及显式注释/活动核对/Hevy CSV 已进入候选源码。正文自动插图保持关闭，详情按指标和来源切换。日报、晨晚报、周报、月报现共用账户结果限定的报告视图；单设备记录仍完整保留供查询和图表。具体资格由[数据合同](../data-contracts.md#设备归属与账户汇总)负责，渠道展示由[报告与渠道](../reports.md#曲线图与图表-api)负责。

2026-11-03 的只读响应与 APK 核对已纠正 band merged 和压力日头的来源解释，并找到密集心率“只建索引、未建下载任务”的根因。候选增加完整归档任务与原始活动 PB 解码；私密本地预览已确认两台设备原始心率和 App merged 心率可独立查看，未知虚拟条目另列。协议证据及解释边界见[Zepp 来源核对](../zepp.md#多设备来源核对)，本计划不保存个人数值、样本数量或原始响应。

这些是本地候选修改与有限的真实只读取证，尚未部署、刷新生产事实或发送 PushPlus。本次最终后端分组回归为 3,064 项通过、17 项跳过，quick/docs/package 均通过；实际私密输入经内存数据库保存、读回和报告构建核对，设备心率与账户心率数量保持一致，报告选中 App 睡眠与 HRV。此前失败和主动中止的运行不计通过。心率三路核对不等于所有指标齐全，也不等于用户已确认各周期报告与 App 一致。

## 接下来做什么

1. 固定候选 SHA，按本次已通过的目标与 quick/backend/docs/package 检查进入隔离候选验收；新增修改须按影响补验。继续核对报告无设备 fallback、查询三路保留、账户缺失局部降级、不同周期与截止时刻、完整归档分片及原始 PB 校验。
2. 基于候选重新生成私密日报、晚报、上一完整周/月预览，与用户 App 核对心率、压力、Charge、睡眠午睡及负荷。已有心率三路证据只用于其明确来源；readiness 按已核实的 App 记录形状准入，仍需对照候选实际展示，不能由缺少 ID、其它占位或设备结果补齐。
3. 单设备最终睡眠仍需核对厂商 `nativeAppDataProcessor` 路径；原始模式字节不冒充最终分期或分数。压力上传前已在本地择取，尚未证实可恢复被择除设备压力的其它接口；缺路保持未取得，不宣称硬件不支持。
4. `fileInfo` 达到 2,000 项上限时目前标部分覆盖，继续验证分页方案与窗口完整性；仅元数据模式不能代表样本已下载。呼吸频率仍需核对 UTC 日桶、采样锚点和本地跨日裁切，未确认前不宣称本地夜间口径已经修正。
5. 对贡献设备字段及来源策略 schema 按[部署流程](../deployment.md)验证加法 DDL 与反向 DDL，保留现库。先在隔离环境按原始 journal 验证旧标签、band/压力 scope、日负荷及 readiness 定向重解析差异，确认不会新旧来源重复；生产刷新和重算须经过候选验收，不能仅更新代码或排版就宣称历史已修正。
6. 图表继续留在详情；恢复正文图表或真实 PushPlus 测试需用户明确授权，并分别验证阅读效果、反馈链接、运输预算与最终接收。Hevy 仍需脱敏实际导出验证日期、单位、同日多场、映射和关联防重复；解除或更改关联要有带 revision 的显式操作。

## 怎样算完成

- 本次候选的本地目标与 quick/backend/docs/package 检查完成，失败修复后重验通过。
- 候选服务器 schema、加载路径、API 读取、worker 分析和历史快照状态验证通过；部署与原始记录刷新结果分别留证。
- 用户确认实际报告与 App；设备、账户、未知来源不互相替代，尚未取得的指标保持明确缺口。
- 显式输入的身份、幂等、修订历史与重算经实际验收；无未授权通知或 Hevy 账户连接。PushPlus 接收效果单独确认。
- 发布并完成必要验收后删除本计划，将持续有效规则留在主责文档。
