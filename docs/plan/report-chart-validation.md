# 验证图表数据与报告接收效果

[改动计划](README.md) · P1 · 状态：服务器候选和实际日报验证，待用户 App 对照及后续缺口

## 现在是什么情况

来源隔离的图表 API、独立 SVG/HTML 详情、午睡、厂商七日负荷、readiness 修订及显式注释/活动核对/Hevy CSV 已进入候选源码。已部署版正文不插图，详情按指标和来源切换；用户新要求仅改晨报和晚报，本地候选增加晨报睡眠时间带、晚报压力微图与有方向/条件的短总结，日报查询不改。日报、晨晚报、周报、月报现共用账户结果限定的报告视图；单设备记录仍完整保留供查询和图表。具体资格由[数据合同](../data-contracts.md#设备归属与账户汇总)负责，渠道展示由[报告与渠道](../reports.md#曲线图与图表-api)负责。

2026-11-03 的只读响应与 APK 核对已纠正 band merged 和压力日头的来源解释，并找到密集心率“只建索引、未建下载任务”的根因。候选增加完整归档任务与原始活动 PB 解码；私密本地预览已确认两台设备原始心率和 App merged 心率可独立查看，未知虚拟条目另列。协议证据及解释边界见[Zepp 来源核对](../zepp.md#多设备来源核对)，本计划不保存个人数值、样本数量或原始响应。

2026-11-03 经明确授权完成加表加字段切换、六十天离线来源刷新与最近三天归档补采；实际日报快照已按 App 结果生成并由 API 读回。所有本次维护和预览链路抑制通知，未额外发送 PushPlus。本次最终后端分组回归为 3,064 项通过、17 项跳过，quick/docs/package 均通过；实际私密输入经内存数据库保存、读回和报告构建核对，设备心率与账户心率数量保持一致，报告选中 App 睡眠与 HRV。此前失败和主动中止的运行不计通过。心率三路核对不等于所有指标齐全，也不等于用户已确认各周期报告与 App 一致。

## 接下来做什么

1. 后续修改固定候选 SHA 并按影响补验；本次服务器隔离目标测试、合成样例、加法及反向 DDL、实际数据子集和服务路径已验证。继续核对报告无设备 fallback、查询三路保留、账户缺失局部降级、不同周期与截止时刻、完整归档分片及原始 PB 校验。
2. 基于候选重新生成私密日报、晚报、上一完整周/月预览，与用户 App 核对心率、压力、Charge、睡眠午睡及负荷。已有心率三路证据只用于其明确来源；readiness 按已核实的 App 记录形状准入，仍需对照候选实际展示，不能由缺少 ID、其它占位或设备结果补齐。
3. 单设备最终睡眠仍需核对厂商 `nativeAppDataProcessor` 路径；原始模式字节不冒充最终分期或分数。压力上传前已在本地择取，尚未证实可恢复被择除设备压力的其它接口；缺路保持未取得，不宣称硬件不支持。
4. `fileInfo` 达到 2,000 项上限时目前标部分覆盖，继续验证分页方案与窗口完整性；仅元数据模式不能代表样本已下载。呼吸频率仍需核对 UTC 日桶、采样锚点和本地跨日裁切，未确认前不宣称本地夜间口径已经修正。
5. 继续核对保守保留的旧无来源依据行：本次不删除无法区分 band/SEC_HR 的历史记录，报告仅排除与新有依据账户事实精确一致的重复投影，不宣称所有历史图表已清理。六十天以外未定向刷新；单次分析仍超30秒目标，部署补采与后台任务并发曾触发写锁，独占完成后恢复。事务收敛归[同步写锁计划](sync-write-transactions.md)负责。
6. 晨晚报微图先提交真实快照私密预览（晚报注明是否为上一完整日或当前未结束日），未做视觉验收不声称接收效果通过。已获授权的仅睡眠/压力正文图须验证反馈链接和运输预算，额外真实 PushPlus 测试仍需明确授权；日报和周月报不恢复图墙。Hevy 仍需脱敏实际导出验证日期、单位、同日多场、映射和关联防重复；解除或更改关联要有带 revision 的显式操作。

## 怎样算完成

- 本次候选的本地目标与 quick/backend/docs/package 检查完成，失败修复后重验通过。
- 候选服务器 schema、加载路径、API 读取、worker 分析和历史快照状态验证通过；部署与原始记录刷新结果分别留证。
- 用户确认实际报告与 App；设备、账户、未知来源不互相替代，尚未取得的指标保持明确缺口。
- 显式输入的身份、幂等、修订历史与重算经实际验收；无未授权通知或 Hevy 账户连接。PushPlus 接收效果单独确认。
- 发布并完成必要验收后删除本计划，将持续有效规则留在主责文档。
