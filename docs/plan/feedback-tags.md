# 用手机实际提交一次报告反馈

[改动计划](README.md) · P2 · 状态：入口已有，等待用户实际提交

## 现在是什么情况

**反馈页已经做好，缺的是从手机推送打开并成功提交的完整验证。**

晨报和晚报可附一次性链接，填写今天感觉、训练用力程度（RPE）、酸痛部位和行为标签。测试已覆盖一次性、过期和用户隔离；当前计划还没有实际提交的验收结果。使用规则见[报告反馈链接](../operations.md#报告反馈链接)。

## 接下来做什么

1. 用户自愿从手机上的晨报或晚报打开链接，填写一次真实想记录的反馈，不为测试虚构感受。
2. 核对反馈归属的用户和日期、保存结果，以及对应日期的分析任务是否完成。
3. 再次打开同一链接，确认提示已使用，不会重复保存或再次提交。

## 怎样算完成

- 用户能打开页面、完成提交并看到明确结果。
- 反馈写入正确日期，重新分析已完成；不能只看到“已排队”就宣布报告更新。
- 重开链接不会重复写入；仅打开、关闭或不填写页面都不会产生反馈。
- RPE 必须关联已完成训练，真实反馈和链接令牌只在私有环境核对，不放进仓库。

反馈页目前还有“没记录就说没完成”的问题，另按[反馈状态计划](feedback-record-status.md)修正。两项分别验收：实际提交成功不能证明状态措辞已修好，状态修正也不能代替手机提交验证。本项不新增字段、不要求用户回复 PushPlus，也不让 Hermes 代填；没有实际提交就继续保留待验证。
