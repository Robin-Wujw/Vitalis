# 修复历史 DailyHealth 指标来源与局部回放边界

[改动计划](README.md) · P1 · 状态：新解析与报告隔离已实现，历史精确修正待开发

## 现在是什么情况

旧解析将 `activeMinutes` 和 `totalBurningDuration` 合并为 `active_minutes`，且没有保存匹配的源字段。新解析已分离 `vendor_burning_minutes`，报告不再把来源不明的旧日级活动分钟用于比较；加密原文和旧事实保持可审计，不能靠日期或数值相等猜测原字段。

现有同步只 upsert 同名指标。`replay source-journal` 可以限制输入 journal，但 `replay apply` 会替换所选日期内七类事实，不能限制为单一指标或流；仅回放 DailyHealth 后应用会删除该窗口内未参与回放的其他事实。现有 diff 对日指标只比较值和单位，也不能完整审阅来源字段修正。

## 接下来做什么

1. 用合成数据复现字段更名与其它来源/训练记录并存，先完善 diff 对来源、资格和获取时间的比较。
2. 实现有明确用户、流、journal 和指标影响范围的修正合同及 API；原文不可变，保留无法证明归属的旧事实，禁止扩大为整窗口替换。
3. 核对新事实的 journal 引用仍指向同用户来源，写入触发有界分析任务和通知抑制；验证失败回滚及重复执行。
4. 生成可审阅的真实只读 diff，再在明确修正范围内执行；不使用通用 replay apply 代替局部修复。

## 怎样算完成

历史中能够由原文证明的字段已准确修正，其它用户、来源、睡眠与训练不变；未知归属保持未知，来源元数据和 API 合同可核对。完成实现、合成验收及实际范围验收后删除本计划。
