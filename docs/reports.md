# 报告阅读与渠道

[文档导航](README.md) | [快速开始](quickstart.md) | [Agent 与客户端](agents.md)

Vitalis 的报告先展示已保存的事实和统计范围，再给出由这些事实支持的分析与建议。缺失日期不补零，未知训练日不当作休息日；只有影响当前结论的缺口才会在对应位置提示。

## 四类报告

| 报告 | 当前周期 | 主要回答的问题 |
| --- | --- | --- |
| 晨报 | 最近结束的主睡眠、前一日活动和当天可用信息 | 今天应优先关注什么？ |
| 晚报 | 用户本地当天，截至生成时刻 | 今天做了什么，今晚怎样收尾？ |
| 周报 | 目标日本地日历周之前的完整周，默认周一至周日 | 哪些模式重复出现？ |
| 月报 | 目标日本地历月之前的完整月 | 长期方向如何，下月改什么？ |

分析引擎也保留明确的滚动窗口模式。滚动周使用“近 7 日”，滚动月使用“近 28 日”，不会伪装成自然周或自然月；周期元数据会标记 `period_mode=rolling`。服务生成的默认报告使用日历周期，跨月、月长变化和时区边界按用户配置处理。

周期结束和数据完整是两个概念。报告中的 `period_end` 说明统计范围，`as_of` 说明数据看到哪一刻；当目标本地日尚未结束时，报告不会把它当成完整日。报告的事实、比较和建议来自同一分析快照，迟到数据需要新的分析修订，不会静默改变已经发送的正文。

## 如何理解正文

报告中的数字应和单位、有效日数或记录数一起阅读。个人中位数或均值描述的是同一用户的可比历史，不是医学正常值；设备分数、热量和睡眠分期保持其来源标签。不同设备、来源、计重口径或单位不能直接混成一个比较。

有名称且满足展示条件的动作会直接显示名称、组数和次数。未知动作、未知重量单位或未核实日期继续保持未知；系统不会把设备观察改写成用户确认，也不会把建议自动记成目标接受或完成。

没有足够数据完成某项比较时，正文会在受影响的位置说明实际缺口，例如“本周仅有 2 晚睡眠记录，暂不比较趋势”。不涉及的可选指标不会固定生成缺失清单。正常数据也不会附加方法论、通用免责声明或要求用户回复的段落。

## PushPlus 与 Hermes

PushPlus 是单向阅读出口。晨报、晚报、周报和月报应在消息正文中独立可读；发送成功只记录投递状态，不代表已读、接受或完成。PushPlus 不提供回复入口，因此报告不会要求回复、确认目标或等待反馈。

Hermes 是可选的互动入口。用户主动追问时，可以解释同一快照的计算依据；当前回答确实缺少关键信息时，才按需追问。用户明确提供疲劳、疼痛、计划或目标意图后，才通过受权用例写入反馈或目标。写入失败必须如实说明，不修改已经发送的报告。

两种渠道共享事实和分析规则。Hermes 新增的反馈只进入后续分析输入，不回写旧快照；关闭 Hermes 不影响 PushPlus 报告的生成、调度和投递。
