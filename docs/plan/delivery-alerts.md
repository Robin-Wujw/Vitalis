# 漏发告警的第二通道

[改动计划](README.md) · P2 · 前置：用户选定通道（2026-10-13 决定暂时只记在库里，2026-10-14 再次确认）

## 为什么

投递目标、独立于 worker 的告警检查和漏发记录已上线（见[运维](../operations.md)），数据流停更和 Zepp 凭据失效也写进同一张告警表，但事件只写在数据库里：晨报没发或 worker 冻住时，用户仍要自己去查 API 才会知道。10/09、10/10、10/12 三次漏发都是用户先发现的。

## 改什么

- 选定不依赖 PushPlus 的第二通道：邮件（SMTP 授权码，凭据放环境文件），或 Hermes（由 Hermes 定时读取 `GET /api/delivery-alerts` 转发到它自己的聊天渠道）。
- `vitalis alerts check` 对新事件经该通道发一次；发送失败保留事件、下次重试，已送达的事件不再发。

## 验收

- 合成测试：发送成功、失败后重试、同一事件只发一次。
- 服务器上用测试目标演练一次（停掉 worker 超过 30 分钟），确认告警能收到。
