# 日级特征表与日常计算路径

[改动计划](README.md) · P1

## 为什么

服务器只有 1.6 GB 内存，SQLite 约 1.3 GB。日报分析会把高频样本整段读进内存，10/09 因此卡在写锁和 swap 上，现在靠每个指标的样本预算截断止血。10/12 预算下仍不够：在生产库副本上实测，单次分析（目标日 10/11）峰值 RSS 362 MB，超过 worker 原来 250M 的 `MemoryHigh`，worker 两次整进程冻住，当天晨报没发；worker 上限因此临时提到 500M/640M，降回 250 MB 以内后再收回。EWMA 准备度、TRIMP 负荷、多变量异常筛查、T+N 训练反应和 FDR 关联都还是影子模式，却每天在日常路径上计算。

## 改什么

- 入库时按天算好每个信号的值、样本数、覆盖和来源，写进日级特征表；日常分析只读这张表，高频样本只在补算时读取。
- 个人基线（中位数/MAD、EWMA）按天增量更新，不再每次回读 28–90 天原始数据。
- 关联分析和月报改到凌晨离峰批处理。
- 每个影子模块写明进入产品的条件和验收指标；进入产品前不在日常路径计算，也不进渲染。
- 日报路径预算 30 秒、150 MB，超出时记录失败原因。

## 验收

- 在生产库只读副本上回放最近 90 天：新旧路径的日报事实一致（差异逐项列明），耗时和峰值内存在预算内。
- 去掉样本预算截断后，日报不再出现部分数据标记。
