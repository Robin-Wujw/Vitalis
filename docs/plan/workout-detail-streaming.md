# 训练明细拿全

[改动计划](README.md) · P1 · 相关：[力量容量与肌群负荷](strength-load.md)

## 为什么

单次训练明细的响应超过 4 MB、2 万个 JSON 对象或 8 万个分隔符时，按 `resource_limit` 整个跳过（`src/vitalis/adapters/zepp/client.py`）。9/28 以来有 75 次同步因此失败，最近每次同步的明细分片仍被跳过。长时间训练的逐秒心率、分圈、配速和力量组数都缺失，训练负荷只能用厂商汇总，跑步卡和力量负荷都依赖这些明细。

## 改什么

明细已改为先落盘再流式解析和分批写入，结构上限只数 JSON 结构本身（字符串里的分隔符不再计数），总大小上限 32 MB。还差：

- 补拉过去被跳过的明细，进度写进覆盖账本。
- 在服务器 worker 的内存上限下实测最大的真实明细，记录耗时和峰值内存；逐字节扫描在 20 MB 级响应上可能很慢，必要时换成更快的扫描。

## 验收

- 合成的 20 MB 明细在 worker 内存上限内解析完成并写入，峰值内存记录在测试里。
- 生产上被跳过的明细补齐后，同步里不再出现 `resource_limit`。
