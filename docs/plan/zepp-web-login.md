# 确认网页登录可靠，再删除旧插件入口

[改动计划](README.md) · P0 · 状态：网页登录已有，待实际验证和旧入口清理

## 现在是什么情况

**不用插件的登录页已经做好；剩下的是确认它能长期使用，再删掉旧入口。**

现有实现包括电脑网页登录、令牌加密保存、尝试自动续期，以及续期失败后的重新登录链接。访问方式见 [Zepp 连接](../zepp.md#网页登录主入口)和[运维配置](../operations.md#zepp-网页登录与重新登录)。

历史记录显示：2026-10-14 真实账号登录成功，并启动首次 180 天历史回填。这不等于回填已完成，也不等于自动续期已经在真实账号上成功。

原计划把 2026-10-28 作为“两周后检查”的日期，**不是到期自动删除插件的授权或验收结果**。目前仍需补齐实际使用证据。

## 接下来做什么

1. 核对首次历史回填是否完成、之后的晨报和晚报是否正常，并检查连续两周使用中是否出现登录阻断。
2. 下次凭据失效时，验证真实账号能否自动续期。若该接口不可用，去掉自动续期，只保留重新登录链接，并验证这条路径能恢复同步。
3. 回填、日常报告和连续两周稳定性有证据后，再安排删除浏览器插件、书签入口及 `VITALIS_PAIRING_ALLOWED_ORIGINS`；同步清理相关路由、打包资源、测试和文档引用，避免留下死入口。

自动续期与插件退役分别记录。若一直没遇到凭据失效，续期仍是待验证；是否在这之前退役插件要明确决定，不把“时间到了”或“登录过一次”当作依据。

## 怎样算完成

- 有回填完成、晨晚报正常及连续两周使用的记录，而不只是一次登录成功。
- 自动续期经真实验证可用，或已明确改为重新登录且能恢复同步；不能留下“应该能续期”的假设。
- 密码不保存，令牌只加密保存；日志、明文存储和响应中不泄漏凭据。
- 删除旧入口后，链接检查及 `uv run --locked --extra dev python tools/check.py all --ci` 通过，并按发布流程验收。

## 开发时注意

旧插件仍是仓库资源和测试的一部分，不能只删一个目录。先核对[连接路由](../../src/vitalis/entrypoints/api/routes/connect.py)、[打包配置](../../pyproject.toml)及[检查脚本](../../tools/check.py)。不为清理入口迁移或删除健康数据库；本次文档整理也不执行上述删除。
