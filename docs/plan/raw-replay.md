# 原始响应留存与离线回放

[改动计划](README.md) · P2

## 为什么

解析器修正后，只能重新请求 Zepp 才能修复历史数据。同步已把原始响应加密写进不可变 journal，`vitalis replay source-journal` 能把它回放进独立的离线用户（见[数据合同](../data-contracts.md)），但回放前不列出新旧事实差异，也不能对当前用户撤销写入，策略改动也没有先在历史上比较的流程。

## 改什么

- 加密保存不可变的原始响应，附 payload 哈希、观测/获取时间、原始 schema 版本和解析器版本。
- 分析运行保存输入清单。
- 提供离线回放入口：用新解析器重放原始响应，列出新旧事实差异后再写入。
- 策略改动（例如准备度权重）先在历史数据上回放比较，再上线。

## 验收

- 合成测试：同一原始响应用两个解析器版本回放，差异可列出，写入可撤销。
- 留存数据加密，不进日志和样例；容量和保留期限写进[运维](../operations.md)。
