# Vitalis

把穿戴设备记录和日常反馈，整理成看得懂、用得上的健康报告。

> **编辑样稿，不是当前功能审计**。以下展示建议采用的产品叙述和阅读顺序。维护者必须依据当前实现补齐并验证快速开始、支持状态、实际链接与许可证，才能把它作为仓库 README 发布。正文中的报告为目标体验和合成示例。

Vitalis 是一个面向自托管场景的健康与训练数据助手。它帮助你回顾睡眠、活动和训练，观察与自身习惯的变化，并把下一步建议和依据放在一起。

你可以通过 **PushPlus 自动接收完整报告**，直接阅读，不需要回复消息。也可以选择接入 **Hermes 对话**，追问依据、补充自己的感受，或明确调整目标。

两种方式共享 Vitalis 的数据与分析。只使用 PushPlus 也能获得完整报告；Hermes 是可选的互动入口，不是推送的前置条件。框架不需要接触穿戴平台密码或直接读取 Vitalis 数据库。

## 你能用它做什么

**开始一天**。 晨报关注昨晚睡眠、当前可用状态和今天值得注意的事。

**结束一天**。 日报回顾已记录的活动与训练，分析训练变化，帮助安排今晚。通过 Hermes 明确记录过的感受可以成为后续分析依据。

**回顾一周或一个月**。 周报观察重复模式；月报关注长期方向和下一阶段目标。数据不够时会说明缺口，而不是补出结论。

## 报告是什么样的

以下是合成数据，用于展示阅读方式：

> **相同重量下，弯举每组多完成 2 次**。
> 今天步数 7,460 步，步行 32 分钟，力量训练 45 分钟。
> 二头肌弯举：每手 10 kg，3 组 × 12 次；上次是同样重量、3 组 × 10 次。下次可以先保持当前重量，观察能否再次完成每组 12 次。

报告直接展示数据、分析和建议。缺口影响结论时才简短提示，例如：“本周仅有 2 晚睡眠记录，暂不比较趋势。”

## 快速开始

这一节发布前必须由执行者在当前工作区完成实测，不应猜测包名或命令。

最终需要写清楚：所需运行环境、获取项目、安装依赖、使用独立演示数据、生成并打开第一份报告，以及如何安全停止演示。每一步使用可复制命令，并展示用户应看到的结果。

演示不应要求真实 Zepp 凭据，也不应自动发送通知。需要真实数据时，再进入数据接入指南。

## 接入自己的数据

数据接入指南应先说明当前支持的来源和限制，再带你完成授权、同步和检查。字段或设备仍处于验证阶段时，应明确标为实验性，不用“全部支持”概括。

报告只使用已经取得且符合条件的记录。没有同步、来源不支持和真实数值为零是不同情况。

## 自动接收 PushPlus 报告

配置推送后，按自己选择的时间接收晨报、日报、周报和月报。每份正文包含数据、分析和建议，不要求回复或确认。

当前 PushPlus 接入不收集回答。没有主观感受或目标反馈时，报告照常生成；系统不会把沉默当成拒绝或未完成。推送成功也不代表你已经接受其中的建议。

发布版在此链接到已经核验的推送设置和排障文档；不虚构回复按钮或另一个未实现的反馈页面。

## 可选：通过 Hermes 对话

Hermes 等框架使用 Vitalis 提供的 API 或产品 Skill 查询报告、查看依据，并在获得你的明确授权后提交反馈或请求新的分析。

只有真实对话中有必要时才追问。你明确提供并授权记录的反馈可以用于后续报告；仅阅读报告或讨论一个建议，不会自动创建目标。

Agent 不负责重新计算健康指标，也不能把自己猜测的疲劳、疼痛或训练内容写成你的事实记录。

## 数据和使用边界

Vitalis 不是诊断工具，也不是实时急救监测服务。消费设备数据可以帮助观察习惯和变化，但不能替代专业医疗评估。

数据是否离开你的部署环境，取决于你启用的模型和通知集成。产品文档应明确列出每种集成会发送什么信息；不要笼统承诺所有情况下都不会外发。
