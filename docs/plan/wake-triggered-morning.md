# 晨报醒来窗口的一周验收

[改动计划](README.md) · P0 · 相关：[漏发告警的第二通道](delivery-alerts.md)

## 为什么

晨报已改成跟着醒来时间走（规则见[运维](../operations.md)）。判断“可信睡眠”的两条阈值（主睡眠至少 3 小时、醒来不早于窗口开始前 3 小时）只依据 10/11 一例夜间上传的半截睡眠定下，还没在真实作息上验证过。

## 改什么

- 醒来窗口从 2026-10-13 起在服务器上运行；满一周后（2026-10-20）运行 `vitalis wake-check --user <用户> --days 7 --end 2026-10-20`，它逐日列出醒来时间、探测次数、晨报同步排队时间、晨报生成时间、醒来后到晨报的分钟数，以及晨报是否在最终醒来时间之前就开始（半截睡眠）。
- 有半截睡眠触发或真实早醒被拖到窗口结束时，调整阈值或改用更直接的完成信号。

## 验收

- 一周记录给用户看过：醒来后到晨报的中位差不超过一个探测间隔加 10 分钟，且没有基于半截睡眠发出的晨报（`wake-check` 的 `passes` 为真）。
