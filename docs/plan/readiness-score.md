# 准备度评分接入晨报

[改动计划](README.md) · P1

## 为什么

0–100 准备度（HRV 状态、睡眠、静息心率、近期负荷四项加权，附影响最大的 3 个因素）已在离峰批处理里影子运行（算法见[数据合同](../data-contracts.md)），还没有替换晨报训练安排依据的计票结论。

## 改什么

- 用 `vitalis shadow run --days 30` 在历史上补算，再用 `vitalis shadow report readiness --user <用户> --days 30` 把逐日分数、因素、计票结论和厂商 Readiness 对比给用户看。
- 用户确认后，晨报关键记录显示准备度和 3 个因素，DecisionEngine 用分数段代替计票结论；不一致的日子先逐日讨论再定权重。

## 验收

- 对比结果给用户看过并确认；接入后合成测试覆盖各分数段的安排，真实样例发给用户确认后上线。
