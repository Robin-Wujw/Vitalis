# Vitalis

> **让穿戴设备的数据，变成每天真正可执行的健康与训练决策。**

Vitalis 是一个面向个人长期数据的 Health Intelligence Engine。

它持续理解你的睡眠、HRV、静息心率、活动、训练负荷和主观反馈，建立个人基线，
识别近期变化，观察训练后的身体响应，并把结果交给 Hermes 或其他 Agent，生成清晰、
可解释的中文健康与训练建议。

Vitalis 不是健康问答机器人，也不是让 LLM 看一堆原始数据后自由发挥。所有指标、
趋势、状态和训练决策都由确定性引擎计算；Agent 只负责调用、解释和交互。

> 当前阶段：可运行、持续开发中的 pre-production 产品。首个完整数据生态为 Zepp、
> Balance 2 与 Helio Strap。

## Vitalis 每天回答什么

- 昨晚睡眠和恢复相对我的个人基线怎么样？
- 今天适不适合训练？应该跑步、练力量、恢复，还是休息？
- 如果训练，强度、时长和具体内容应该是什么？
- 最近一周和近 28 天发生了哪些值得关注的变化？
- 某次训练让我恢复了多久？同类训练对我通常有什么影响？
- 我的睡眠、训练负荷、HRV 和静息心率之间有哪些长期个人关联？

## 产品体验

下面展示的是输出结构示意，不代表任何真实用户或医疗结论。

### Morning：今天怎么练

```text
今日结论

恢复指标整体接近个人正常范围，今天按正常强度训练。

今天做什么

主要：轻松跑 30–45 分钟
1. 热身 6–8 分钟
2. 轻松跑 18–30 分钟，保持能连续说出完整短句
3. 冷身 5–7 分钟

有余力时，晚些时候可做 20–30 分钟恢复性活动；不做也不影响主要安排。

为什么
- 昨晚睡眠时长接近个人基线。
- 夜间心率变异性接近个人基线。
- 本周力量次数已完成，今天优先补足跑步。
```

### Evening：今天发生了什么

```text
今日回顾

活动：已完成训练
负荷：处于近期正常范围
主观体感：等待记录

今晚重点
训练后优先补充恢复，保持规律入睡。

明日预判
将在今晚睡眠和次日 HRV 到齐后重新判断。
```

Morning 是计划，Evening 是复盘。两者不会用不同措辞重复同一份内容。

### Weekly 与 Monthly：不只看今天

| 视图 | 回答的问题 |
| --- | --- |
| Daily | 今天的睡眠、恢复和训练决策是什么？ |
| Weekly | 这周训练、睡眠、活动和恢复是否平衡？ |
| Monthly | 最近 28 天相较此前 28 天发生了什么？ |
| Trends | 7 / 28 / 90 天的方向、变化和波动如何？ |
| Events | 哪些偏离正在持续、改善或已经恢复？ |

Weekly 和 Monthly 都由 Vitalis 直接从规范化数据计算，不由 Agent 拼接日报。

### Training Response：训练之后，身体怎么响应

Vitalis 将每次训练视为一次可追踪的训练记录，观察随后 1–3 天的身体变化：

```text
一次训练
  → 次日 HRV / 静息心率 / 睡眠
  → 主观用力程度、疲劳与酸痛
  → 是否有重叠训练或缺失窗口
  → 回到个人基线所需时间
  → 同类训练的个人响应模式
```

随着记录积累，建议不再只依据通用经验，而会逐渐参考你对跑步、力量训练和其他具体
运动模式的真实历史响应。

### Ask Vitalis：自然语言访问健康智能

Hermes 可以把自然语言问题路由到对应的 Vitalis 结果：

```text
“我今天适合跑步吗？”
→ 给出今天的训练判断与具体内容

“为什么只建议低强度？”
→ 解释数据事实、综合判断和行动建议

“这次跑步对我影响怎么样？”
→ 回顾训练后的身体响应

“我最近有什么长期规律？”
→ 总结有足够数据支持的个人模式
```

Hermes 不重新计算趋势、相关系数、恢复时间或训练内容。

每日训练输出不是“跑步或力量随便选一个”的模板。Vitalis 先按健康状态做安全门控，
再按用户选择比较 7/28 天跑步与力量缺口，或依据最近一次正式训练做跑步/力量轮换，
输出一个主项和至多一个可选项，并明确两者可分开完成还是只能二选一。结构化档案保留
剂量、证据、冲突检查和限制；每日推送只呈现今天要做什么、原因，以及真正会改变行动
的提醒。跑步机可用性和坏天气替代方式属于个人偏好；未接入天气源时不会编造天气判断。

## 核心能力

| 能力 | Vitalis 提供什么 |
| --- | --- |
| 个人基线 | 理解属于你的正常范围，而不是套用单一人群阈值 |
| 睡眠智能 | 时长、规律性、时点、分期时间轴、醒来次数、睡眠心率与 HRV 的趋势解释 |
| 恢复判断 | 综合 HRV、静息心率、睡眠与近期负荷，不依赖单一指标 |
| 训练决策 | 健康门控优先，可按 7/28 天缺口或个人轮换偏好安排跑步和力量的一主一辅行动计划 |
| 运动识别 | 区分跑步、力量等具体运动，并说明识别置信度 |
| 跑步分析 | 设备心率区间、公里分段、实际运动时间、配速、步频、步幅、功率、跑姿、可比跑步基线、心率漂移、间歇结构与课型 |
| 训练状态 | 最大摄氧量、乳酸阈值、PAI 强度来源与训练负荷分别解释，不合成黑箱分数 |
| 力量分析 | 已确认动作、组次与负重、动作模式、肌群恢复、工作/休息结构和训练分化 |
| 冲突控制 | 避免质量跑、长跑和腿部力量在 48 小时内连续堆叠 |
| 周期回顾 | Daily、Weekly、固定 28 天 Monthly 与前周期比较 |
| 健康事件 | 偏离的发现、持续、改善、恢复和独立确认状态 |
| 训练闭环 | 建议 → 实际训练 → RPE / 疲劳 → 生理响应 → 个人模型 |
| 个人关联 | 发现睡眠、训练、HRV 与静息心率之间有数据支持的长期模式 |
| Agent 交互 | 让 Hermes 在明确边界内回答、解释并记录反馈 |
| 数据健康 | 分开记录每条流的云端抓取、解析、写入和最新样本时间 |

## 为什么结果值得信任

### 数据事实、系统推断和行动建议彼此分开

Vitalis 明确区分设备测到的事实、引擎形成的判断，以及最终建议。Agent 不能把推断
包装成原始测量，也不能凭空补充一个更“像专家”的结论。

### 个人基线优先于通用阈值

同一个 HRV 数字对不同的人意义不同。Vitalis 关注今天相对你自己的正常范围如何，
偏离是否持续，以及睡眠、静息心率和训练负荷是否同时变化。

### 不混合不同设备的生理流

Balance 2 与 Helio Strap 的 HRV 不会被平均成一个数字。Vitalis 为每项指标选择一个
连续、基线覆盖更完整的主设备，另一台只做静默校验；只有分歧会降低当天结论把握时
才提醒用户。指标、来源、设备和单位在结构化档案中始终保留独立身份。

### 缺失就是缺失

Vitalis 不用零值、旧结果、厂商分数或模板建议填补缺失观测。关键数据不足时，它会
停止判断并说明缺少什么。

力量训练同样遵守这一原则：只有厂商明确提供或用户确认的动作，才会作为具体动作进入
分析。单靠心率只能估计工作段和休息段，不能判断做的是卧推、深蹲还是其他动作。

### 关联不等于因果

个人关联用于发现值得关注的历史模式，不用于证明某个行为导致某个生理结果。重叠
训练、覆盖率和潜在混杂都会进入限制与置信度。

## 当前支持

- Zepp 云端历史同步与浏览器官方登录配对
- Balance 2 与 Helio Strap 来源边界
- 睡眠、HRV、静息心率、心率、活动、训练、压力、SpO2 等可用数据
- 跑步、力量训练等具体运动类型、训练负荷和运动详情
- 中文 Morning、Evening、Weekly、Monthly 与按需解释
- Hermes Read / Analyze / Act 工具

Vitalis 当前用于个人健康趋势与运动决策支持，不是医疗设备，不诊断疾病，也不替代
医生对症状、检查结果或治疗方案的判断。

## 项目方向

Vitalis 的目标不是“分析一下手环数据”，而是持续建立个人健康状态模型：

```text
数据 → 分析 → 决策 → 行动 → 响应 → 学习 → 更好的下一次决策
```

当前重点是继续完善训练响应、主观反馈和个人模式闭环。在现有确定性能力稳定之前，
不会用不可解释的综合健康分或复杂预测模型替代清晰的事实与规则。
