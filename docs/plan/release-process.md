# 发布流程减负

[改动计划](README.md) · P1 · 用户确认后才改 SOP

## 为什么

10/10 一天在服务器上构建了 10 个版本、切换服务 7 次；每次合并 `main` 后还要按最终 SHA 再构建、再切换一次。所有验证都跑在 1.6 GB 内存的生产机上，而这台机器资源本来就紧张。

## 改什么（提案）

- 预发布验证改在本地，用生产库的只读副本；服务器只做最后的候选验收。生产数据离开服务器前要先和用户确认存放和删除方式。
- 候选验收通过后让 `main` 快进到候选提交，最终 SHA 与已验收候选相同，省掉第二次构建和切换。
- 报告类改动走“真实样例审阅 → 发布”的短流程。

## 验收

- 用户确认后更新[发布与部署 SOP](../deployment.md)和 `AGENTS.md`，下一次发布按新流程完整走一遍。
