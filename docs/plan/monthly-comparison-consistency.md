# 让月报摘要和正文使用同一套比较

[改动计划](README.md) · P1 · 状态：待开发

## 现在是什么情况

**同一份月报不能在摘要说“变好了”，正文却按另一套数据说“变差了”。**

月报已能生成，也已有按有效天数比较的规则。剩余问题集中在摘要：

- 自然月报告可能把两个设备的同名指标都写出来，却不说明来源，形成两条方向相反的结论。
- 近 28 天的滚动月报摘要直接使用趋势结果，可能与正文的平均值、总量或所选来源不同。

因此不是重做月报，也不是直接照搬周报阈值；是让摘要沿用正文已经选定的事实和比较方法。

## 接下来做什么

1. 为每个指标明确正文采用的主要来源和统计方法：睡眠用平均时长；训练负荷沿用当前“有负荷记录日均”的比较，总量保留为事实，不用不同月长的原始总量判断变化。不能在摘要里换成另一来源或中位数。
2. 同一指标只给一条主要变化。确有必要展示其他来源时明确标注，不把不同设备的结果合成一句话。
3. 摘要沿用正文的数据完整性要求；前后任一期记录不足，就说明无法比较，不硬给上升或下降。
4. 保留可供 API 查阅的分来源比较依据；自然月和滚动月分别处理，不假设当前两条路径已经都保留了完整趋势。

## 怎样算完成

- 测试覆盖：多设备方向相反、总量与中位数方向相反、不同月长、前后期记录不足。
- 自然月与近 28 天报告都通过；摘要和正文在来源、日期、数值、方向及缺口说明上保持一致。
- HTML 与 Markdown 使用相同事实，API 仍能查到来源和比较依据。
- 私下提供真实预览，经用户确认后按发布流程上线；当前规则更新到[报告与渠道](../reports.md)。

## 开发入口

从[月报摘要 `_key_changes`](../../src/vitalis/intelligence/monthly.py)及[月报测试](../../tests/test_monthly_profile.py)开始，先补失败案例，再修改摘要选取。自然月已有按月长和有效日数计算的逻辑，应保留；滚动月和自然月的比较门槛也不能未经验证改成同一个固定天数。
