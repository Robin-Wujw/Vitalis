# 建立动作到肌群的正式映射与来源资格

[改动计划](README.md) · P1 · 相关：[数据合同](../data-contracts.md)、[Zepp](../zepp.md)、[报告与渠道](../reports.md)

## 为什么

当前 Zepp 动作目录已核验代码与显示名，但 1,133 个条目的 `canonical_exercise_id` 均为空，目录没有主、次肌群字段。`lap_62` 的已映射名称因此只进入观测展示，不进入已确认动作、肌群恢复或处方；逐组记录已同步也可能无法判断训练部位。报告应解释这一来源限制，不能把它写成同步失败或“识别 0/N”。

现有 `EXERCISE_KNOWLEDGE` 使用名称子串匹配，不能直接承担整个目录的肌群映射。例如公开目录中的“俯卧弹力绳腿弯举”会因“弯举”被归入肱二头肌；“腿弯举”和手臂弯举需要不同的规范动作身份。只补几个词或用模型根据名称猜肌群，不能解决映射资格和未知动作的问题。

## 改什么

- 建立版本化、可审阅的规范动作映射：用来源命名空间和动作代码对应稳定的规范动作标识，再登记动作模式、主要肌群、次要肌群及依据。目录代码、厂商显示名、规范身份和肌群解释分别保存；无法明确对应时保留未知，不用宽泛名称子串回退。
- 为每条肌群关系保留来源、适用动作或器械变式、依据定位和映射版本。厂商只提供名称时，肌群解释须另有明确依据，不能声称肌群由手表直接测量；肌群参考应表述为动作的典型受力部位，不等同于实际训练质量、有效组或恢复完成。
- 分离来源资格和处方资格：厂商参考显示名、已核验规范动作、明确设备记录、用户确认和存在冲突的记录各保留身份。明确哪些可以用于参考汇总、哪些可以进入容量、恢复、分化和训练处方；仅新增名称或肌群参考不得自动升级处方资格，用户确认优先但不能由系统代填。
- 参考肌群汇总在分析层计算并保存范围、可用记录数和缺口，渠道只做投影。未知动作不补肌群，缺失训练日不当休息；重量单位或负重口径未知时，不计算容量或 1RM。参考记录与合资格记录分开统计，不把参考肌群混入现有恢复、负荷和分化决策。
- 处理已保存记录与快照时，遵守当前受影响日期重算流程，保留来源、组序、每组次数、原始重量与单位、观测和获取时间；不在 renderer 临时补映射，不原地改写历史快照，不因映射更新重复推送。

## 复现与验收

- 先用合成数据补失败测试，覆盖腿弯举与肱二头肌弯举、中英文同名歧义、不同器械变式、目录外代码、暂定目录、只有名称而没有明确身份，以及用户确认与设备记录冲突。核对每个已声明映射的主次肌群和依据，不能仅以“能匹配到”作为正确标准。
- 对登记的规范动作映射做全量唯一性、命名空间、来源证据和版本检查；未登记部分明确保持未知，不以猜测凑齐目录覆盖率。普通解析、流式解析、持久化、`ProfileLoader`、`StrengthAnalyzer` 与自然周分析使用同一资格规则。
- 单独验证参考展示与处方边界：只有参考名的 `lap_62` 可显示有来源的参考说明，但不得提高已确认动作覆盖或触发肌群恢复、分化和动作剂量；已达到明确资格的动作才能进入其获准的分析。每个允许升级的条件需有独立测试，不能把添加肌群字段当成授权。
- 日报、晚报和周报均区分“已有手表参考名称”和“没有可用于判断部位的动作明细”，不把单位缺失、映射缺失和同步缺失混为一个问题；展示不声称用户确认，不把多个不同次数的组改成平均组次。
- 运行目录、解析、力量分析、ProfileLoader、周报、决策和报告目标测试及 `tools/check.py backend`、`tools/check.py docs`。若输出合同或分析规则变化，同步版本、唯一主责文档和生成样例；通过自然周期合成端到端验收后，再按发布 SOP 核验实际读取路径和保存快照。
