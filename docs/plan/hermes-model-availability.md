# 恢复 Hermes 模型可用性并验收新工作流

[改动计划](README.md) · P0 · 状态：候选实现完成，待模型选择与实际验收

## 现在是什么情况

2026-11-10 隔离测试发现运行中 Hermes 配置的模型名被同一兼容端点以 HTTP 400 拒绝，模型目录也不再包含该配置。网关进程 active 不能证明对话可用。生产配置没有擅自更换；本次只向可用候选模型发送合成数据，未发送真实健康数据或 Telegram 测试消息。

同端点 `claude-sonnet-4-6` 已实际调用 API，合成测试没有未授权写入，但仍出现虚构操作命令、为只读权限查询请求确认、过度解释厂商 TSB 的行为，未通过工作流验收，不能作为已验证的生产替代。

报告与客户端候选已接入已核实睡眠时序、每日目标、稀疏体重和独立厂商负荷。Hermes 流程优先读取保存报告，区分源数据缺失与分析陈旧，并保持 coach-policy 和显式反馈权限。长期规则见[智能体集成](../agents.md)与[报告与渠道](../reports.md)。

## 接下来做什么

1. 用户选定可用替换模型；使用同端点、同模型和最终 Skill 在隔离 home 做真实合成对话验收，不把关键词测试或其它模型成功当作生产模型成功。
2. 核对报告优先、陈旧报告与新事实分开、TSB 不生成训练许可、稀疏体重不判减脂、coach-policy 拒绝时不写、只讨论疲劳不保存、明确记录但没评分时不猜分。回答只能引用已存在的 API 操作，不能虚构产品页面。
3. 按部署 SOP 切换全部服务及实际安装的 Skill，保留既有会话；模型配置按选定结果修改。用户从本人私聊验证真实读取与回答，不自动向 Telegram 发测试消息。

## 怎样算完成

选定模型在真实隔离评估中完成上述场景，候选已部署且本人私聊确认可用后删除本计划。源数据、原始会话和模型凭据不进入仓库；脱敏测试证据与私密预览分别保存。
