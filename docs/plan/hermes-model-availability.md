## 现在是什么情况

此前运行中 Hermes 的模型配置被兼容端点拒绝；网关进程 active 不能证明对话可用。用户随后指定新接口并提供独立凭据，真实 SDK 的模型目录和工具调用已验证可用。新地址、密钥位置和运行配置仅在私密部署环境维护，旧 key 不用于新地址。

2026-11-11，固定 `gpt-6.1-terra` 与候选 `c98d87c26c99fdf91db362d1e0433ef871699641` 完成 15 轮真实模型合成对话。人工逐轮核对回答、工具调用和 HTTP 记录：新睡眠与旧报告分开解释，普通报告不主动展示 ATL/CTL/TSB，晚报保留截止时刻，燃脂分钟不替代训练分钟，周比较保留窗口与覆盖，原始 readiness 不升级为评分，稀疏体重与 TSB 不生成减脂或训练许可。未授权分析与资料修改没有写入；唯一一次反馈 POST 仅保存用户明确给出的日期和身体疲劳 4 分，使用持久幂等键并 GET 核对。

主评估末轮通过 `Path.home()` 读取了生产安装的公开 API 文档；该文档整体版本不同，但所查反馈输入 schema 与候选一致，命令记录没有健康记录或凭据访问。随后启用 Hermes 的隔离终端 home，补跑疲劳讨论、缺评分澄清、明确评分记录三轮，全部通过；工具路径均位于隔离目录。评估只使用合成数据，未发送 Telegram 测试消息。生产 SOUL 与候选模板一致；部署仍须核对实际安装 Skill 和运行路径。

查询效率仍有余地：晚报多读一次日报，燃脂解释多读一次完整日报，目标与体重组合问题在报告已有 TSB 时仍补查该指标。简单算术仅用于已返回值的单位换算、差值或展示比例，没有重算健康评分或生成生理结论；这些冗余读取尚未消除。

报告与客户端候选已接入已核实睡眠时序、每日目标、稀疏体重和独立厂商负荷。Hermes 流程优先读取保存报告，区分源数据缺失与分析陈旧，并保持 coach-policy 和显式反馈权限。长期规则见[智能体集成](../agents.md)与[报告与渠道](../reports.md)。
