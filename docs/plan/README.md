这里只放还没做的改动，一项一个文件。已经实现的行为写在对应主责文档里，历史看 git log，这里不留“已完成”清单。

## 维护规则

- 开始某项改动前先读它的文件；文件写清为什么做、改什么、怎么验收。
- 改动按[发布与部署 SOP](../deployment.md) 上线时，在同一次合并里删除该文件和下表对应行，把仍然有效的规则写进主责文档。
- 做的过程中发现的后续工作，新建文件并加入下表；不再需要的条目直接删除。
- 用户能看到的变化（报告内容、推送版式）先发真实样例给用户确认，再部署。
- 优先级：P0 本周，P1 2–4 周，P2 1–2 个月，P3 2–3 个月。

## 目标闭环

连接 → 回填 → 首次分析 → 晨报 → 训练和活动 → 晚报 → 反馈或纠错 → 按影响范围重算 → 下一版报告 → 周报/月报验证。PushPlus 只做单向推送；提问、确认和记录反馈走 Hermes 或推送页里的反馈入口。
