## 1. 目的

本文档是每次仓库工作会话的执行契约。它使规划、实现、测试、提交和项目文档保持同步，确保未完成的工作可见且可复现。

## 2. 必须遵循的工作流程

每项仓库任务，包括功能、修复、重构、配置、研究和文档，都必须按以下顺序执行：

1. 在不修改业务代码的情况下，检查仓库状态、现有文档和相关测试。只读检查可以进行到足以形成准确计划为止。
2. 在实现或执行任何其他会改变状态的命令之前，在本文档中编写按部分划分的详细 TODO 列表，并向用户展示。
3. 一次只实现一个已列出的部分。如果证据改变了范围或方法，必须在继续前更新计划；不得静默偏离计划。
4. 为该部分所改变的行为新增或更新单元测试。
5. 运行该部分的聚焦测试。只有测试通过后，才能勾选该部分。
6. 当行为、API、配置、项目结构、平台支持或测试数量发生变化时，更新相关项目 Markdown 文档。
7. 每个主要计划部分通过其聚焦测试和文档检查后，在开始下一个主要部分前只提交该部分。不得将多个已完成的主要部分合并到一个最终提交中，也不得包含无关的用户修改。
8. 在结束会话前运行完整测试套件并记录结果。如果最终验证需要修复，则新增或重新打开一个计划部分，并在验证后单独提交该修复。
9. 所有计划部分和最终验证通过后，推送已完成的分支。除非用户明确要求将工作保留在本地，或推送被外部因素阻塞，否则远程分支包含实现之前，本地实现都不算完成。

## 3. 完成规则

- `[ ]` 表示待处理或尚未验证。
- `[x]` 表示该部分的实现、对应测试、文档以及聚焦验证均已完成。
- 部分实现的部分仍保留 `[ ]`；必须在其下方注明当前状态。
- 失败或跳过的验证必须明确记录，不得描述为已完成。
- 每项功能或修复都必须有一个 TODO 项、聚焦单元测试覆盖、相关 Markdown 更新，以及该项自己的可追溯提交，之后才能勾选该项。
- 每个部分完成时更新 TODO 复选框；不得将所有进度更新推迟到会话结束。
- 在验证日志中记录已推送的分支和提交。如果推送失败，交付项保持未勾选，并在不暴露机密的前提下记录确切阻塞原因。
- 必须保留现有用户修改。无关清理不属于任务范围。
- 项目文档中的测试总数必须来自最近一次完整测试运行。
- 仅文档性质的研究笔记无需应用测试覆盖，但必须记录其范围、来源、边界和验证命令。

### 3.1 预生产新数据专用策略

本仓库处于预生产阶段。每次变更都必须只面向当前契约，以及该契约实现后摄入的数据。

- 不要保留向后兼容性。应删除被取代的端点、字段名、模式、工具、类、代码路径和测试，而不是保留别名或适配器。
- 不要为旧契约创建的数据新增旧数据读取器、版本分支、双重读写、迁移、回填、重新解释规则或转换任务。
- 现有本地数据可丢弃。当模式或规范化契约发生变化时，清除受影响的旧数据，并按当前契约重新摄入，而不是让新代码理解旧表示形式。
- 不要从已废弃字段、端点标签、文本提示、无关指标、默认值或另一设备流推断新的必填字段。
- 新摄入数据中的缺失观测必须继续明确表示为缺失数据，并可能产生 `INSUFFICIENT_DATA`；这是数据质量导致的暂缓判断，不是兼容性回退。绝不要用零值或编造的数值替代缺失测量。
- 测试和夹具必须只验证当前契约。实现发生变化时，删除已废弃的契约预期。
- 例外情况必须有新的、明确的用户指令，且指令需点名要保留的确切旧契约或数据集。要求改进或扩展 Vitalis 的一般性请求不授权开展兼容性工作。

## 26. 已验证密集心率与夜间融合

日期：2026-08-30

目标：解码 Zepp 的秒级心率文件，在夜间分析中安全使用它们，完成多设备恢复简报，并消除计划交付路径对交互式终端 proxy 设置的依赖。

### 已实现合同

- 官方 Android 流程已验证为 `fileInfo` index -> `queryDownUrlList` -> signed HTTPS ZIP -> `DailySecondHeartBeat` protobuf。一个 heartbeat block 包含 Unix-second 开始时间及其后连续的整数心率值；`255` 表示数据缺失。
- ZIP entry/device 分配使用全局一对一最大 interval-overlap 匹配。歧义映射、不安全 URL、格式错误的 archive、无效 protobuf wire type、超大内容和非心率值均被拒绝。

- analysis loader 仅查询实际睡眠窗口，将每台设备的秒级值归约为分钟中位数，并最多保留 35 夜。当前夜晚优先选择覆盖充分的上臂数据流，并且只与其自身可用历史比较。HRV 保持独立的 canonical 同设备基线和次要设备佐证合同。
- 密集 archive 一次解码并持久化一个文件。这限制了多日同步的内存使用，避免在一次大型写入前保留整个窗口的 sample。
