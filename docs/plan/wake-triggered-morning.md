# 晨报醒来窗口的一周验收

[改动计划](README.md) · P0 · 相关：[漏发告警的第二通道](delivery-alerts.md)

## 为什么

晨报已改成跟着醒来时间走（规则见[运维](../operations.md)）。判断“可信睡眠”的两条阈值（主睡眠至少 3 小时、醒来不早于窗口开始前 3 小时）只依据 10/11 一例夜间上传的半截睡眠定下：手机在入睡后不久同步，Zepp 把上传时刻当成醒来时间，这条记录一直留到真正醒来后才更新。阈值还没在真实作息上验证过。

## 改什么

- 服务器运行一周，每天记录醒来时间、首次看到可信睡眠的时间、晨报受理时间和探测次数（worker 日志已有探测和晨报同步两行）。
- 核对两类错误：夜里上传的半截睡眠触发了晨报；真实的早醒被拖到窗口结束才发。按结果调整阈值，或改用更直接的完成信号。

## 验收

- 一周记录给用户看过：醒来后到晨报受理的中位差不超过一个探测间隔加 10 分钟，且没有基于半截睡眠发出的晨报。
